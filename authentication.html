Authentication

The Partner API uses the OAuth 2.0 client credentials flow. Your integration exchanges a client ID and secret for a short-lived access token, then sends that token on every request.

Your system                                   Capacity Partner API
    |  POST /api/v1/auth/token                        |
    |  client_id + client_secret  ------------------> |
    |  <------------------  access_token (~15 min)    |
    |                                                 |
    |  GET /api/v1/ping                               |
    |  Authorization: Bearer <access_token>  -------> |
    |  <------------------------------  200 / 401     |

Credentials​

CredentialFormatNotes
Client IDText, issued by CapacityNot secret, but do not publish it.
Client secretText, issued by CapacitySecret and case-sensitive.

Sandbox and production credentials are issued separately. See Environments.

Request a token​

POST /api/v1/auth/token with a form body (application/x-www-form-urlencoded):

FieldValue
grant_typeclient_credentials (the only grant supported)
client_idYour client ID
client_secretYour client secret

You can send the ID and secret as an HTTP Basic Authorization header instead of form fields. If you send both, the header is used.

  • cURL
# Form fields
curl -X POST "https://uat-api-partner.capacityllc.com/api/v1/auth/token" \
-H "Content-Type: application/x-www-form-urlencoded" \
--data-urlencode "grant_type=client_credentials" \
--data-urlencode "client_id=$CAPACITY_CLIENT_ID" \
--data-urlencode "client_secret=$CAPACITY_CLIENT_SECRET"

# Or HTTP Basic
curl -X POST "https://uat-api-partner.capacityllc.com/api/v1/auth/token" \
-u "$CAPACITY_CLIENT_ID:$CAPACITY_CLIENT_SECRET" \
-d "grant_type=client_credentials"

The response:

FieldMeaning
access_tokenThe token. Treat it as an opaque string: do not parse it or rely on its contents.
token_typeAlways bearer.
expires_inSeconds until the token expires (about 900).
.issued, .expiresWhen the token was issued and expires, as RFC 1123 dates in GMT.

Use the token​

Send it on every request except the token request:

Authorization: Bearer eyJhbGciOiJSUzI1NiJ9.EXAMPLE-ONLY.signature

Reuse tokens​

Request a token once and reuse it until about 60 seconds before it expires. Requesting a token for every call is slower for you and may be limited in future.

  • Node.js
  • Python
  • C#
let cached = { token: null, expiresAt: 0 };

async function getToken() {
if (cached.token && Date.now() < cached.expiresAt - 60_000) {
  return cached.token;
}
const response = await fetch("https://uat-api-partner.capacityllc.com/api/v1/auth/token", {
  method: "POST",
  headers: { "Content-Type": "application/x-www-form-urlencoded" },
  body: new URLSearchParams({
    grant_type: "client_credentials",
    client_id: process.env.CAPACITY_CLIENT_ID,
    client_secret: process.env.CAPACITY_CLIENT_SECRET,
  }),
});
if (!response.ok) throw new Error(`Token request failed: ${response.status}`);
const body = await response.json();
cached = { token: body.access_token, expiresAt: Date.now() + body.expires_in * 1000 };
return cached.token;
}
import os, time, requests

_cached = {"token": None, "expires_at": 0.0}

def get_token() -> str:
  if _cached["token"] and time.time() < _cached["expires_at"] - 60:
      return _cached["token"]
  response = requests.post(
      "https://uat-api-partner.capacityllc.com/api/v1/auth/token",
      data={
          "grant_type": "client_credentials",
          "client_id": os.environ["CAPACITY_CLIENT_ID"],
          "client_secret": os.environ["CAPACITY_CLIENT_SECRET"],
      },
      timeout=30,
  )
  response.raise_for_status()
  body = response.json()
  _cached.update(token=body["access_token"], expires_at=time.time() + body["expires_in"])
  return _cached["token"]
public sealed class CapacityTokenProvider(HttpClient http, string clientId, string clientSecret)
{
  private readonly SemaphoreSlim gate = new(1, 1);
  private string? token;
  private DateTimeOffset expiresAt;

  public async Task<string> GetTokenAsync(CancellationToken cancellationToken = default)
  {
      await gate.WaitAsync(cancellationToken);
      try
      {
          if (token is not null && DateTimeOffset.UtcNow < expiresAt.AddSeconds(-60))
          {
              return token;
          }

          using var response = await http.PostAsync("https://uat-api-partner.capacityllc.com/api/v1/auth/token",
              new FormUrlEncodedContent(new Dictionary<string, string>
              {
                  ["grant_type"] = "client_credentials",
                  ["client_id"] = clientId,
                  ["client_secret"] = clientSecret,
              }), cancellationToken);
          response.EnsureSuccessStatusCode();

          using var json = JsonDocument.Parse(await response.Content.ReadAsStringAsync(cancellationToken));
          token = json.RootElement.GetProperty("access_token").GetString()!;
          expiresAt = DateTimeOffset.UtcNow.AddSeconds(json.RootElement.GetProperty("expires_in").GetInt32());
          return token;
      }
      finally
      {
          gate.Release();
      }
  }
}

If a call returns 401, the token may have expired early or been revoked. Get a new token and retry the call once. If it fails again, stop and check your credentials.

Errors​

ResponseCauseFix
400 {"error": "invalid_credentials", ...}Wrong or missing client ID or secret, or the credentials are disabled.Check both values and the case of the secret. Check you are not using sandbox credentials in production.
400 {"error": "unsupported_grant_type"}grant_type is missing or not client_credentials.Send grant_type=client_credentials.
503 {"error": "temporarily_unavailable", ...}The token service is briefly unavailable.Retry after a few seconds, with backoff.
401 on any other callMissing, malformed or expired token.Get a new token and retry once.

Keep credentials safe​

  • Store the secret in a secrets manager or an environment variable. Never commit it or write it to logs.
  • Call the API from your servers only. Never put the secret in a browser, mobile app or anything a customer can download.
  • Do not share one credential between unrelated systems; ask for a separate one.
  • If a secret may have been exposed, contact Capacity Support straight away so it can be replaced.

Existing integrations​

Integrations built for the previous Capacity REST API, at api-integration.capacityllc.com, may keep calling POST /Token with their existing credentials. It behaves the same as POST /api/v1/auth/token. New integrations must use POST /api/v1/auth/token at api-partner.capacityllc.com. See Existing integrations.

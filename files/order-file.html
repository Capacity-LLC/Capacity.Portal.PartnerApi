Order file

The order file sends Capacity the orders you want shipped. Each line is one order line, with the order details repeated on every line of the order.

DirectionYou to Capacity
FolderIN in your folder on ftp01.capacityllc.com
WhenEvery 5 minutes from 00:48 to 23:18, Sunday to Friday; every 10 minutes on Saturday, US Eastern
After processingCapacity moves the file to an archive and adds a batch number to the front of its name

The flat file rules apply to every layout on this page.

Required rules​

  • Header row, then one line per order line. Capacity reads columns by position, so every line has every column of your layout, in order, even when a value is empty.
  • EndOfLine is always EOL. It is the last column of versions 3.0, 4.0 and 4.1.
  • One PickTicketID per order. All lines of an order share the same PickTicketID, and the order-level columns (ship-to, ship method, dates and amounts) must be identical on every line of the order.
  • Unique order numbers. Use a new PickTicketID for every order. If Capacity receives a PickTicketID it already has, it holds the new order as a duplicate for review.
  • Your owner code. ClientCode must be your two-character owner code on every line. A file with another owner code is rejected.
  • A ship-to name. Send ShipBusinessName, ShipName or both. Release lines take the name from the EDI purchase order.
  • Known SKUs. Every ItemProductID must already exist in Capacity, as a Capacity SKU or an alternate SKU. Send new products first.
  • Whole-number quantities. Quantities are whole numbers of units, digits only, with no thousands separator.
  • Dates. Use MM/DD/YYYY, US Eastern. YYYY-MM-DD is also accepted.

Ship methods​

ShipMethod must match one of the ship methods set up for your account, character for character. Capacity gives you the list during onboarding and adds methods on request. Email itedi@capacityllc.com to ask for a new one.

An order with an empty or unknown ShipMethod is still imported. Capacity holds it until the ship method is corrected, then releases it to the warehouse. Send a ship method from your list to avoid the delay.

The ship confirmation reports the carrier service actually used, under Capacity's own service name. See the ship confirmation file.

Quantities​

  • ItemOrderQuantity is the quantity your customer ordered.
  • ItemShipQuantity is the quantity to ship. Leave it empty to ship the ordered quantity.
  • When you send ItemShipQuantity, Capacity ships that quantity, even when it is lower than the ordered quantity. A value of 0 creates a line with nothing to ship.

Releasing an EDI purchase order​

Some retailers send their purchase orders to Capacity by EDI (an X12 850) on your behalf. Capacity holds each of these orders until you release it, so that you decide what ships and when.

To release one, add a line to an order file for each product to ship:

  1. Set ReleaseFlag to Y.
  2. Set CapacityImportID to Capacity's import number for the EDI order. Capacity gives you this number.
  3. Repeat the PONumber, RetailerCode and StoreNumber of the EDI order.
  4. Give the order your own PickTicketID, and set ClientCode, ItemProductID, ItemOrderQuantity and ItemShipQuantity.
  5. Leave the ship-to columns and ShipMethod empty. Capacity uses the address and routing of the EDI order.

The third line of each sample file below is a release line.

If an order cannot be imported​

Each order in a file is imported on its own. If Capacity asks you to resend an order, send only that order in a new file, not the whole file again.

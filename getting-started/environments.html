Environments

The Partner API has two environments. They have different base URLs, different credentials and different data. Nothing you do in one affects the other.

SandboxProduction
Base URLhttps://uat-api-partner.capacityllc.comhttps://api-partner.capacityllc.com
CredentialsSandbox client ID and secretProduction client ID and secret
DataTest data. Orders are not fulfilled or shipped to real customers.Live. Orders are picked, packed and shipped.
Use it forBuilding and testing your integrationYour live integration, after go-live

Use the Sandbox | Production switch at the top of every page to change the base URL in all code samples. The coloured band under the navigation bar shows which one is selected.

New integrations use api-partner

New integrations must use api-partner.capacityllc.com. Capacity does not support new integrations at any other address.

Existing integrations: api-integration.capacityllc.com​

Integrations built against the previous Capacity REST API call https://api-integration.capacityllc.com. That address is moving to this same API, so existing integrations keep working without changes:

  • The previous paths (for example POST /api/order/create and POST /Token) keep working for existing integrations at both api-integration.capacityllc.com and api-partner.capacityllc.com.
  • The request and response formats do not change.
  • api-integration.capacityllc.com is for existing integrations only. It is not offered to new clients: a new integration calling an /api/v1/ path there gets 410 Gone with the api-partner address to use.

Capacity will ask existing integrations to move to api-partner.capacityllc.com and the /api/v1/ paths. See Paths and versions and the legacy path map in the API reference.

Rules that prevent mistakes​

  • Keep the base URL in configuration. Your code should read one setting for the base URL and one for each credential. Going live, or moving from api-integration to api-partner, is then a configuration change, not a code change.
  • Never mix the pairs. A sandbox token is rejected by production and a production token is rejected by the sandbox. A configuration that points production credentials at the sandbox URL fails in a way that is easy to misread as "wrong password".
  • Label your logs. Log which environment each request went to, and the X-Correlation-ID you sent.

Paths and versions​

Every current path starts with /api/v1/. Paths without /v1/ (for example /api/order/create) belong to the previous Capacity REST API and are kept only for integrations built against it. A new integration that calls one gets 410 Gone with the current path in the message. See the API reference, where those paths are marked deprecated.

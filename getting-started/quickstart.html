Quickstart

Follow these steps in the Sandbox. You will get a token, test the connection, submit a test order and cancel it. Allow about 15 minutes once you have credentials.

You need: a terminal with curl, or Node.js 18+, Python 3.9+ or .NET 8. Choose your language once and every sample on the site follows it. These exact requests have been tested against the sandbox.

Get sandbox credentials​

Email itedi@capacityllc.com to request Partner API sandbox credentials. You receive:

ItemExample in these docsWhat it is
Client IDYOUR_SANDBOX_CLIENT_IDIdentifies your integration.
Client secretYOUR_SANDBOX_CLIENT_SECRETA password for your integration. Case-sensitive.
Owner codeZZThe 2-character code for your account. You send it as clientcode on orders and client on inventory requests.
Ship method and retailer codesGROUND, WEBThe codes agreed for your account during onboarding.

Sandbox and production credentials are different. Sandbox credentials do not work in production, and production credentials do not work in the sandbox.

Keep the secret out of code

Load the client secret from an environment variable or a secrets manager. Never commit it, put it in a URL, or send it from a browser.

The samples read the credentials from environment variables:

Set your sandbox credentials
export CAPACITY_CLIENT_ID="YOUR_SANDBOX_CLIENT_ID"
export CAPACITY_CLIENT_SECRET="YOUR_SANDBOX_CLIENT_SECRET"

Get an access token​

Exchange the client ID and secret for a bearer token. The request is a form post, not JSON.

  • cURL
  • Node.js
  • Python
  • C#
POST /api/v1/auth/token
curl -X POST "https://uat-api-partner.capacityllc.com/api/v1/auth/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "grant_type=client_credentials" \
  --data-urlencode "client_id=$CAPACITY_CLIENT_ID" \
  --data-urlencode "client_secret=$CAPACITY_CLIENT_SECRET" \
  -H "X-Correlation-ID: $(uuidgen)"
POST /api/v1/auth/token
const response = await fetch("https://uat-api-partner.capacityllc.com/api/v1/auth/token", {
  method: "POST",
  headers: {
    "Content-Type": "application/x-www-form-urlencoded",
    "X-Correlation-ID": crypto.randomUUID(),
  },
  body: new URLSearchParams({
    grant_type: "client_credentials",
    client_id: process.env.CAPACITY_CLIENT_ID,
    client_secret: process.env.CAPACITY_CLIENT_SECRET,
  }),
});

console.log(response.status, await response.json());
POST /api/v1/auth/token
import os
import uuid

import requests

response = requests.post(
    "https://uat-api-partner.capacityllc.com/api/v1/auth/token",
    headers={
        "X-Correlation-ID": str(uuid.uuid4()),
    },
    data={
        "grant_type": "client_credentials",
        "client_id": os.environ["CAPACITY_CLIENT_ID"],
        "client_secret": os.environ["CAPACITY_CLIENT_SECRET"],
    },
    timeout=60,
)
print(response.status_code, response.json())
POST /api/v1/auth/token
using var http = new HttpClient();
using var request = new HttpRequestMessage(HttpMethod.Post, "https://uat-api-partner.capacityllc.com/api/v1/auth/token");
request.Headers.Add("X-Correlation-ID", Guid.NewGuid().ToString());
request.Content = new FormUrlEncodedContent(new Dictionary<string, string>
{
    ["grant_type"] = "client_credentials",
    ["client_id"] = Environment.GetEnvironmentVariable("CAPACITY_CLIENT_ID")!,
    ["client_secret"] = Environment.GetEnvironmentVariable("CAPACITY_CLIENT_SECRET")!,
});

using var response = await http.SendAsync(request);
Console.WriteLine($"{(int)response.StatusCode} {await response.Content.ReadAsStringAsync()}");
Expected response · 200
{
  "access_token": "eyJhbGciOiJSUzI1NiJ9.EXAMPLE-ONLY.signature",
  "token_type": "bearer",
  "expires_in": 899,
  ".issued": "Mon, 02 Nov 2026 14:00:00 GMT",
  ".expires": "Mon, 02 Nov 2026 14:14:59 GMT"
}

Keep the access_token for the next steps:

Keep the token
export CAPACITY_TOKEN="paste the access_token here"
Reuse the token

The token lasts about 15 minutes. Reuse it until shortly before expires_in runs out; do not request a new token for every call. See Authentication for token caching.

If you getIt meansDo this
400 invalid_credentialsThe client ID or secret is wrong, or the credentials are disabled.Check both values, including the case of the secret. Check you are using sandbox credentials against the sandbox.
400 unsupported_grant_typegrant_type is not client_credentials.Send grant_type=client_credentials.
503 temporarily_unavailableThe token service is briefly unavailable.Wait a few seconds and retry.

A 401 with {"message": "Authorization has been denied for this request."} means the header is missing, malformed (it must be Bearer, a space, then the token) or the token has expired. Get a new token and try again.

Strings and lowercase

Every value in an order is a string, including quantities ("1", not 1). Field names are lowercase.

If an order fails validation you get a 400 that names the field and the pick ticket:

400 Bad Request
{ "message": "Please validate order data. Shipping Address 1 can not be empty for Pick Ticket Id PT-0001001" }
A 400 can mean some orders were accepted

When individual orders fail validation, every valid order in the request is still accepted, and the 400 names one failed order and its reason, not every failure. Resend only the orders that failed: check each against the field rules to find them all.

Nothing was accepted when the 400 is Invalid Input, Unable to validate client., or Please validate order data. with no detail.

The full field list and every response are in Submit orders.

What "cancelled" means

Cancel only works while the order is open and has no shipping or tracking information. Pick tickets should be unique: if two open orders share one, which order is cancelled is not defined.

Go live​

Before you switch to production:

  • Request production credentials. They are separate from your sandbox credentials.
  • Change the base URL to the production URL. Keep it in configuration, not in code.
  • Store the secret in a secrets manager, not in source control or logs.
  • Reuse one token until shortly before it expires.
  • Treat every date and time from the API as US Eastern time. See Dates and time zones.
  • Retry 500, 503 and 504 with backoff, and send an X-Correlation-ID on every request so support can find it. See Errors.

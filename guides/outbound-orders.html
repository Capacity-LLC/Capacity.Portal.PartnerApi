Send orders and track shipments

This guide puts the outbound calls in the order an integration uses them. Each step links to its reference page for every field.

1. Submit orders​

Submit orders (POST /api/v1/outbound/orders) takes one or more orders, each with its lines. You identify each order by your pick ticket (pickticketid); keep it unique per order.

  • A 200 {"accepted": true} means the orders passed validation and are being created in the background, usually within seconds. Always send each order's lines: an order with an empty lines array is skipped without an error.
  • The response carries no Capacity order IDs. Your pick ticket is how you refer to the order afterwards (cancel, ship confirmations).
  • A 400 that names an order means the orders that passed validation were accepted, and the message names one failed order, not every one. Resend only the orders that failed; to find them all, check each against the field rules. See Retrying order submissions before you build retries.
  • A requestedshipdate more than 3 days out normally holds the order as a future order until nearer the date.

2. Cancel, if you need to​

Cancel an order (POST /api/v1/outbound/orders/cancel) cancels by pick ticket. Read order_cancelled in the 200 response: only open orders with no shipping or tracking information can be cancelled. If you cancel in the first seconds after submitting, the order may not exist yet; wait a few seconds and retry.

3. Collect ship confirmations​

There are no callbacks: you poll. Capacity prepares ship confirmations in numbered batches per day.

  1. Your onboarding contact tells you how many batches your account receives per day, and when each is prepared.
  2. For each batch_date (US Eastern), request each batch_num after it has been prepared, with Get shipment confirmations (one item per order line) or Get shipment confirmations by carton (tracking number, SSCC and contents per carton).
  3. Match confirmations to your orders by pickticketid, and make processing idempotent: reading the same batch twice must not ship-confirm an order twice in your system.
  4. A batch with nothing in it is a 200 with {"message": "No records found. Please check input."}, not an empty list. A batch that has not been prepared yet looks the same, so do not treat an early empty answer as final.

Batch 1 starts the evening before. Batch 1 of a date covers confirmations created from 22:00 Eastern the previous evening; the other batches cover the calendar date. Details: Dates and time zones.

4. Follow carrier tracking (optional)​

Get carrier tracking events returns carrier scans for one hour (hour_num 0-23, US Eastern) of a batch_date. Request an hour after it has ended. Events identify the order by capacityOrderNum.

5. Check picked orders (optional)​

Get picked orders returns orders that have been picked and not yet shipped. It is not a general order-status lookup: an order that has not been picked comes back as "not found", and shipped orders are reported by step 3.
